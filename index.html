  1. Windows: open the downloaded lan-root-ca.cer, then choose Install Certificate → Current User.
  2. Choose Place all certificates in the following store → Browse → Trusted Root Certification Authorities. Do not use automatic store selection. Finish the wizard and accept the trust confirmation.

macOS: import the certificate in Keychain Access and set its SSL trust. Linux/Chromebook: import it as a certificate authority in the browser’s certificate settings. Managed devices may need an administrator.

Add a mod
    
Import a ZIP, RAR, 7z or data-only OIV package (up to 128 MiB). Review the detected package, replacement targets and compatibility notes before installing.

    
Supported formats and compatibility
    
      
  • Vehicles: classic add-on DLCs and stock-based replacements for cars, bikes, bicycles, quadbikes, boats, helicopters and planes. Mesh-only replacements can retain stock textures. Replacement conversion imports compatible handling and colour/livery metadata when supplied; otherwise it retains stock settings.
    • 
      
  • Stock vehicles: select “Replace stock assets” for car, bike, boat and aircraft meshes, textures, liveries and existing tuning-part replacements. Normal stock spawns use the replacement; separate add-on conversion uses the matching stock vehicle template. Stock layouts, tuning slots and handling remain unless a compatible handling pack is enabled.
    • 
      
  • World props: classic replacements and retextures for indexed roadside, vegetation, residential, commercial, industrial and other prop archives. Existing model names and map placements are retained; this does not add new maps or prop definitions.
    • 
      
  • Characters: complete non-streamed human skins can register as separate add-on peds with generic male movement, or replace stock characters. Texture packs and existing streamed-ped resources, including Story-player files, use stock replacements.
    • 
      
  • Replacement shaders: translated grandv-shader-pack-v1 ZIPs with WGSL programs, matching installed source hashes and unchanged shader interfaces. Each program compiles with WebGPU before installation and again at launch. DirectX/ReShade sources and DLL injectors need a port; this does not add external textures, new passes or custom uniforms.
    • 
      
  • Graphics: indexed classic cloud/road/global resource textures and standalone x64/textures YTD dictionaries retaining stock texture names; classic visualsettings.dat, stock weather timecycles/modifiers, clouds, lens flares and weather XML. Numeric values merge onto this build’s existing definitions; unsupported fields and sample layouts are reported. ASI reloaders, ReShade and ENB are not used.
    • 
      
  • Weapon settings: weapons.meta can adapt supported damage, recoil, accuracy, clip size, range and timing fields for existing weapons. Existing magazine capacities can also merge from weaponcomponents.meta. New weapon definitions, audio/effect references and ammo types are retained from stock.
    • 
      
  • Handling packs: ZIPs containing handling.meta merge supported physics fields into this build’s existing stock profiles. Disable the package and restart to restore stock.
    • 
      
  • Weapons: 36 stock weapon models, matching attachments, meshes and textures. Existing gameplay stats remain in effect.
    • 
      
  • Clothing, hair and accessories: existing component/prop slots and texture variants. Stock resource packs can combine multiple parts.
    • 
      
  • Animations: YCD dictionaries with clip names; replacing a stock dictionary keeps the existing action and clip names.
    • 
      
  • Resource containers: ZIPs containing unencrypted stock resource RPF archives. RAR4/RAR5 and 7z archives unpack locally before compatibility inspection. Password-protected, multi-part and linked archives are unsupported.
    • 
      
  • For a combined stock resource pack, preserve destination folders such as vehicles.rpf/, banshee_mods.rpf/, v_trees.rpf/, weapons.rpf/ or streamedpeds_players.rpf/player_zero/. Explicit archive/model paths resolve ambiguous filenames.
    • 
      
  • Loose vehicle packs with matching vehicles.meta can use a stock template with the same type/layout (cover and class hints select the closest match). Custom handling and colour presets are adapted; unsupported gearbox values retain stock. Complete compatible carcols/carvariations tuning kits and part models are adapted with separate kit IDs. Custom lights, sirens and audio banks are omitted and reported.
    • 
      
  • FiveM asset wrappers (fxmanifest.lua and __resource.lua) are ignored. OIV containers use validated add/copy mappings for supported resource/handling targets or one compatible vehicle DLC. Archive creation, deletions and XML/text edits are not applied. This does not supply the FiveM runtime.
    • 
      
  • Scripts, executables, encrypted RPFs, newer unsupported resource versions and new weapon/clothing slots are not supported. Resources must fit existing skeletons, metadata and this build's indexed stock slots.
    • 
    

    
    
    
      
Colour grading: import an SDR 3D .cube LUT directly or inside an archive. Sizes 2–65 are resampled to 16³ RGB10 with trilinear lookup. HDR and 1D/shaper LUTs are unsupported. LUT grades overlap SweetFX and RCAS; use one world-composite grade at a time. Restart to apply or disable.

      
Spatial graphics effects (bloom and clarity)
Bloom improves highlight glow through the existing bloom pyramid. Set Graphics & performance → Post-effects to Very high to use the tested bloom path. RCAS sharpens the world before the HUD; its five composite evaluations can reduce frame rate. This is sharpening, not FSR upscaling or ray tracing. Choose the combined pack or its components. RCAS overlaps SweetFX colour packs. Restart after changing toggles; disable to restore stock.

      
Shader examples (ported SweetFX)
Enable one colour shader pack at a time in the table. Restart to apply changes. These affect world rendering; they do not add a menu overlay.
